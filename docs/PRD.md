# BuildLog 제품 요구사항 문서(PRD)

## 1. 문서의 목적

이 문서는 BuildLog 첫 번째 버전을 만들기 위한 제작 주문서입니다. 무엇을 왜 만들고, 사용자가 무엇을 할 수 있어야 하며, 어디까지 완성해야 하는지를 설명합니다.

이 문서는 `mvp.md`에서 정한 범위와 이후 사용자 답변으로 확정한 세부 조건만 다룹니다.

## 2. 서비스 한 줄 설명

BuildLog는 공부한 내용, 앞으로 할 일, 공부 중 만난 오류와 해결 방법을 한곳에 저장하고 다시 찾을 수 있는 개인용 학습 기록 웹사이트입니다.

## 3. 누가 사용하는가

### 주요 사용자

공부하거나 프로젝트를 진행하면서 다음과 같은 기록을 남기고 싶은 사람입니다.

- 오늘 무엇을 공부했는지 기록하고 싶은 사람
- 앞으로 공부할 내용이나 해야 할 작업을 관리하고 싶은 사람
- 개발 중 만난 오류와 해결 방법을 모아두고 싶은 사람
- 여러 컴퓨터와 휴대폰에서 자신의 기록을 확인하고 싶은 사람

### 사용 조건

- 여러 사람이 각각 회원 가입하여 사용할 수 있습니다.
- 사용자는 이메일과 비밀번호로 가입하고 로그인합니다.
- 각 사용자의 기록은 비공개이며 작성한 본인만 볼 수 있습니다.
- 별도의 모바일 앱이 아니라 컴퓨터와 휴대폰에서 접속할 수 있는 웹사이트로 만듭니다.

## 4. 어떤 불편을 해결하는가

공부 기록이 메모장, AI 대화 등 여러 곳에 흩어지면 나중에 어디에 적었는지 기억하기 어렵습니다. 또한 해야 할 일을 놓치거나, 예전에 해결한 오류를 다시 만났을 때 같은 과정을 반복할 수 있습니다.

BuildLog는 다음 불편을 해결합니다.

| 불편 | BuildLog가 제공할 해결 방법 |
| --- | --- |
| 오늘 무엇을 공부했는지 잊어버림 | 학습 기록을 날짜와 함께 저장하고 다시 보여줌 |
| 해야 할 공부나 작업을 놓침 | 할 일을 적고 완료 여부를 체크하게 함 |
| 오류 기록이 여러 곳에 흩어짐 | 오류 메시지, 발생 상황, 해결 방법을 한곳에 보관함 |
| 예전 기록을 찾기 어려움 | 검색과 태그·날짜 조건으로 기록을 찾게 함 |
| 기기가 바뀌면 기록을 보기 어려움 | 로그인하면 컴퓨터와 휴대폰에서 같은 기록을 보여줌 |

## 5. 제품의 기본 원칙

- 기록하고 다시 찾는 핵심 경험에 집중합니다.
- 화면과 사용 방법을 단순하게 만듭니다.
- 메뉴와 안내 문구는 쉬운 한국어를 사용합니다.
- 모든 개인 기록은 작성자 본인에게만 보여야 합니다.
- 서비스의 비밀 설정값을 코드에 직접 적거나 공개하지 않습니다.
- 사용자의 비밀번호를 원래 글자 그대로 저장하지 않습니다.
- 컴퓨터와 휴대폰에서 주요 기능을 사용할 수 있어야 합니다.

## 6. 기능 요구사항

### 6.1 회원 가입

사용자는 이메일과 비밀번호로 계정을 만들 수 있어야 합니다.

반드시 되어야 하는 일:

- 이메일과 비밀번호를 입력하여 가입할 수 있습니다.
- 이미 가입된 이메일을 다시 사용할 수 없습니다.
- 가입에 성공했는지 또는 실패했는지 알기 쉬운 안내를 보여줍니다.
- 가입에 성공하면 바로 로그인된 상태로 대시보드에 이동합니다.
- 비밀번호는 안전하게 변환한 값만 저장합니다.

입력 조건:

- 이메일은 일반적인 이메일 형식이어야 합니다.
- 비밀번호는 8자 이상이어야 합니다.

### 6.2 로그인과 로그아웃

가입한 사용자는 로그인하여 자신의 기록을 이용하고, 사용을 마치면 로그아웃할 수 있어야 합니다.

반드시 되어야 하는 일:

- 올바른 이메일과 비밀번호로 로그인할 수 있습니다.
- 잘못된 정보로 로그인하면 알기 쉬운 안내를 보여줍니다.
- 로그아웃하면 개인 기록 화면에 더 이상 접근할 수 없습니다.
- 로그인하지 않은 사용자는 개인 기록을 볼 수 없습니다.
- 로그인한 사용자도 다른 사용자의 기록을 볼 수 없습니다.

- 로그인 상태는 로그인한 기기에서 7일 동안 유지합니다.

### 6.3 대시보드

대시보드는 로그인한 뒤 가장 먼저 보는 홈 화면입니다. 사용자는 이 화면에서 현재 상황을 빠르게 확인할 수 있어야 합니다.

반드시 보여줄 내용:

- 최근 학습 기록
- 완료하지 않은 할 일
- 아직 해결하지 못한 오류
- 학습 기록, 할 일, 오류 기록의 전체 목록으로 이동하는 버튼

- 각 영역에는 5개 항목을 보여줍니다.
- 학습 기록은 공부한 날짜가 최신인 순서, 할 일은 미완료이면서 마감일이 가까운 순서, 오류 기록은 최근 수정한 순서로 보여줍니다.
- 마감일이 없는 할 일은 마감일이 있는 할 일 다음에 보여줍니다.

### 6.4 학습 기록

사용자는 공부한 내용을 작성하고, 저장된 내용을 읽고, 고치고, 삭제할 수 있어야 합니다.

저장할 정보:

- 제목
- 내용
- 공부한 날짜
- 태그
- 작성일
- 수정일
- 작성한 사용자

반드시 되어야 하는 일:

- 새 학습 기록을 작성하고 저장할 수 있습니다.
- 자신의 학습 기록 목록과 상세 내용을 볼 수 있습니다.
- 자신의 기록을 수정하거나 삭제할 수 있습니다.
- 내용에 마크다운을 사용할 수 있습니다.
- 마크다운의 제목, 목록, 링크, 코드 블록을 읽기 좋은 모습으로 보여줍니다.
- 삭제하기 전에 사용자에게 한 번 더 확인합니다.
- 저장 성공 또는 입력 오류를 안내합니다.

입력 및 목록 조건:

- 제목, 내용과 공부한 날짜는 필수이며 태그는 선택입니다.
- 제목은 최대 100자, 내용은 최대 20,000자입니다.
- 태그는 한 기록에 최대 5개까지 추가할 수 있고, 태그 하나는 최대 20자입니다.
- 태그 내용을 입력하고 `Enter`를 누르면 태그가 추가됩니다.
- 목록은 공부한 날짜가 최신인 순서로 한 번에 20개씩 보여줍니다.

### 6.5 할 일

사용자는 앞으로 공부할 내용이나 프로젝트에서 해야 할 작업을 관리할 수 있어야 합니다.

저장할 정보:

- 할 일 내용
- 마감일
- 완료 여부
- 작성일
- 수정일
- 작성한 사용자

반드시 되어야 하는 일:

- 새 할 일을 작성하고 저장할 수 있습니다.
- 자신의 할 일 목록을 볼 수 있습니다.
- 자신의 할 일을 수정하거나 삭제할 수 있습니다.
- 체크 상자로 완료 또는 미완료 상태를 바꿀 수 있습니다.
- 남은 할 일과 끝난 할 일을 구분해서 볼 수 있습니다.
- 완료하지 않은 할 일만 골라 볼 수 있습니다.
- 삭제하기 전에 사용자에게 한 번 더 확인합니다.
- 저장 성공 또는 입력 오류를 안내합니다.

입력 및 목록 조건:

- 할 일 내용은 필수이고 마감일은 선택입니다.
- 새 할 일은 `미완료` 상태로 저장합니다.
- 미완료와 완료한 할 일을 나누어 모두 보여줍니다.
- 미완료 할 일은 가까운 마감일 순서로 보여주고, 마감일이 없는 항목은 그다음에 보여줍니다.
- 완료한 할 일은 최근 수정한 순서로 보여줍니다.
- 목록은 한 번에 20개씩 보여줍니다.

### 6.6 오류 기록

사용자는 공부나 개발 중 만난 오류를 저장하고, 나중에 해결 방법을 추가할 수 있어야 합니다.

저장할 정보:

- 오류 제목
- 실제 오류 메시지
- 오류가 발생한 상황
- 해결 여부
- 해결 방법
- 태그
- 작성일
- 수정일
- 작성한 사용자

반드시 되어야 하는 일:

- 해결하지 못한 오류도 먼저 저장할 수 있습니다.
- 자신의 오류 기록 목록과 상세 내용을 볼 수 있습니다.
- 자신의 오류 기록을 수정하거나 삭제할 수 있습니다.
- 오류 상태를 `미해결` 또는 `해결됨`으로 바꿀 수 있습니다.
- 오류를 해결한 뒤 해결 방법을 추가할 수 있습니다.
- 아직 해결하지 못한 오류만 골라 볼 수 있습니다.
- 삭제하기 전에 사용자에게 한 번 더 확인합니다.
- 저장 성공 또는 입력 오류를 안내합니다.

입력 및 목록 조건:

- 오류 제목, 오류 메시지와 발생 상황은 필수이며 해결 방법과 태그는 선택입니다.
- 오류 제목은 최대 100자이고, 오류 메시지·발생 상황·해결 방법은 각각 최대 20,000자입니다.
- 태그는 한 기록에 최대 5개까지 추가할 수 있고, 태그 하나는 최대 20자입니다.
- 태그 내용을 입력하고 `Enter`를 누르면 태그가 추가됩니다.
- 상태를 `해결됨`으로 바꾸려면 해결 방법을 반드시 입력해야 합니다.
- 목록은 최근 수정한 순서로 한 번에 20개씩 보여줍니다.

### 6.7 검색과 필터

사용자는 기억나는 단어나 조건을 이용해 예전 기록을 찾을 수 있어야 합니다.

반드시 되어야 하는 일:

- 학습 기록에서 제목과 내용을 단어로 검색할 수 있습니다.
- 오류 기록에서 제목과 내용을 단어로 검색할 수 있습니다.
- 학습 기록과 오류 기록을 태그별로 볼 수 있습니다.
- 학습 기록과 오류 기록을 날짜별로 볼 수 있습니다.
- 오류 기록에서 미해결 항목만 볼 수 있습니다.
- 할 일에서 미완료 항목만 볼 수 있습니다.
- 검색과 필터 결과에는 로그인한 사용자의 기록만 나타납니다.

MVP에서는 학습 기록과 오류 기록을 각각 검색합니다. 서로 다른 종류의 기록을 한 번에 찾는 통합 검색은 만들지 않습니다.

검색 및 필터 조건:

- 영문 대문자와 소문자를 구분하지 않고 검색합니다.
- 검색어, 태그, 날짜와 상태 조건을 동시에 사용할 수 있습니다.
- 여러 조건을 사용하면 모든 조건에 맞는 기록만 보여줍니다.
- 날짜는 시작일과 종료일을 선택하는 기간 방식으로 찾습니다.
- 학습 기록은 공부한 날짜, 오류 기록은 작성일을 날짜 필터의 기준으로 사용합니다.
- 오류 기록은 제목, 오류 메시지, 발생 상황과 해결 방법을 검색합니다.

## 7. 필요한 화면

### 7.1 회원 가입 화면

- 이메일과 비밀번호 입력
- 가입 실행
- 입력 오류와 가입 결과 안내
- 로그인 화면으로 이동

### 7.2 로그인 화면

- 이메일과 비밀번호 입력
- 로그인 실행
- 로그인 오류 안내
- 회원 가입 화면으로 이동

### 7.3 대시보드

- 최근 학습 기록 확인
- 남은 할 일 확인
- 미해결 오류 확인
- 각 전체 목록으로 이동

### 7.4 학습 기록 목록 화면

- 자신의 학습 기록 목록 확인
- 제목과 내용 검색
- 태그와 날짜 필터
- 상세 화면으로 이동
- 새 기록 작성 화면으로 이동

### 7.5 학습 기록 작성·수정 화면

- 제목, 내용, 공부한 날짜, 태그 입력
- 마크다운으로 내용 작성
- 새 기록 저장 또는 기존 기록 수정
- 저장 결과 확인

작성과 수정은 같은 화면을 재사용합니다.

### 7.6 학습 기록 상세 화면

- 저장된 내용을 마크다운이 적용된 모습으로 읽기
- 수정 화면으로 이동
- 확인 후 기록 삭제

### 7.7 할 일 목록 화면

- 할 일 추가
- 할 일 수정과 삭제
- 체크 상자로 완료 상태 변경
- 남은 할 일과 끝난 할 일 구분
- 미완료 할 일만 보기

### 7.8 오류 기록 목록 화면

- 자신의 오류 기록 목록 확인
- 제목과 내용 검색
- 태그와 날짜 필터
- 해결 여부로 필터
- 상세 화면으로 이동
- 새 오류 기록 작성 화면으로 이동

### 7.9 오류 기록 작성·수정 화면

- 오류 제목, 오류 메시지, 발생 상황, 해결 여부, 해결 방법, 태그 입력
- 새 오류 저장 또는 기존 오류 수정
- 저장 결과 확인

작성과 수정은 같은 화면을 재사용합니다.

### 7.10 오류 기록 상세 화면

- 오류 내용과 해결 과정 읽기
- 해결 여부 확인
- 수정 화면으로 이동
- 확인 후 기록 삭제

## 8. 화면 공통 기준

- 기본 화면은 밝은 색으로 만듭니다.
- 주요 메뉴는 `홈`, `학습 기록`, `할 일`, `오류 기록`입니다.
- 작성 버튼과 저장 버튼은 쉽게 찾을 수 있어야 합니다.
- 컴퓨터에서는 넓은 화면을 활용합니다.
- 휴대폰에서는 내용이 화면 밖으로 벗어나지 않고 세로로 자연스럽게 배치되어야 합니다.
- 저장에 성공했거나 입력에 문제가 생겼을 때 안내 문구를 보여줍니다.
- 삭제처럼 되돌리기 어려운 동작은 실행 전에 한 번 더 확인합니다.

세부 디자인:

- 대표 색상은 파란색 계열을 사용합니다.
- 글꼴은 사용 중인 기기의 기본 글꼴을 사용합니다.
- 로고는 별도 그림 없이 `BuildLog` 글자로 표시합니다.
- 컴퓨터에서는 메뉴를 화면 위쪽에 배치합니다.
- 휴대폰에서는 메뉴 버튼을 눌러 메뉴를 엽니다.

## 9. 저장해야 할 데이터

| 종류 | 저장할 내용 |
| --- | --- |
| 사용자 | 사용자 번호, 이메일, 안전하게 변환된 비밀번호, 가입일 |
| 학습 기록 | 기록 번호, 작성한 사용자 번호, 제목, 내용, 공부한 날짜, 태그, 작성일, 수정일 |
| 할 일 | 할 일 번호, 작성한 사용자 번호, 내용, 마감일, 완료 여부, 작성일, 수정일 |
| 오류 기록 | 오류 기록 번호, 작성한 사용자 번호, 제목, 오류 메시지, 발생 상황, 해결 여부, 해결 방법, 태그, 작성일, 수정일 |

학습 기록, 할 일, 오류 기록은 반드시 작성한 사용자와 연결합니다. 서버는 기록을 보여주거나 고치거나 삭제하기 전에 현재 로그인한 사용자가 작성자인지 확인해야 합니다.

## 10. 첫 번째 버전의 완료 기준

다음 조건을 모두 만족해야 BuildLog의 첫 번째 버전이 완성된 것으로 봅니다.

### 계정과 보호

- 새로운 사용자가 이메일과 비밀번호로 가입할 수 있습니다.
- 가입한 사용자가 로그인하고 로그아웃할 수 있습니다.
- 로그인하지 않은 사용자는 개인 기록을 볼 수 없습니다.
- 로그인한 사용자는 자신의 기록만 보고, 수정하고, 삭제할 수 있습니다.
- 비밀번호가 원래 글자 그대로 저장되지 않습니다.
- 비밀 설정 파일과 비밀값이 공개되지 않습니다.

### 학습 기록

- 학습 기록을 작성, 조회, 수정, 삭제할 수 있습니다.
- 마크다운과 코드 블록을 작성하고 읽을 수 있습니다.
- 제목과 내용으로 학습 기록을 검색할 수 있습니다.
- 태그와 날짜로 학습 기록을 골라 볼 수 있습니다.

### 할 일

- 할 일을 작성, 조회, 수정, 삭제할 수 있습니다.
- 체크 상자로 완료 여부를 변경할 수 있습니다.
- 남은 할 일과 끝난 할 일을 구분할 수 있습니다.
- 완료하지 않은 할 일만 골라 볼 수 있습니다.

### 오류 기록

- 해결하지 못한 오류를 저장할 수 있습니다.
- 오류 기록을 조회, 수정, 삭제할 수 있습니다.
- 해결 후 해결 방법을 추가하고 상태를 `해결됨`으로 바꿀 수 있습니다.
- 제목과 내용으로 오류 기록을 검색할 수 있습니다.
- 태그와 날짜로 오류 기록을 골라 볼 수 있습니다.
- 해결하지 못한 오류만 골라 볼 수 있습니다.

### 화면과 저장

- 대시보드에서 최근 학습 기록, 남은 할 일, 미해결 오류를 확인할 수 있습니다.
- 대시보드에서 각 전체 목록으로 이동할 수 있습니다.
- 컴퓨터와 휴대폰에서 모든 주요 기능을 사용할 수 있습니다.
- 새로고침하거나 로그아웃 후 다시 로그인해도 저장한 내용이 유지됩니다.
- 저장 성공, 입력 오류, 로그인 실패 등을 사용자가 알 수 있습니다.
- 삭제하기 전에 확인 절차가 나타납니다.

## 11. 이번에 만들지 않는 기능

다음 기능은 첫 번째 버전에 포함하지 않습니다.

- 다른 사용자에게 기록 공개 또는 공유
- 이미지와 파일 첨부
- 할 일 중요도
- 다크 모드
- 댓글과 좋아요
- 신고
- Google 또는 GitHub 같은 소셜 로그인
- 이메일 인증
- 비밀번호 찾기
- 공부 시간 통계와 차트
- 실시간 알림
- 별도의 모바일 앱
- 모든 종류의 기록을 한 번에 찾는 통합 검색
- 비슷한 오류 기록 추천
- 기록 내보내기와 백업

## 12. 추가로 확정한 내용

- 회원 가입에 성공하면 자동으로 로그인하고 대시보드로 이동합니다.
- 이메일 형식, 비밀번호 길이, 필수 입력 항목과 글자 수 제한을 적용합니다.
- 로그인 상태는 7일 동안 유지합니다.
- 태그는 `Enter`로 추가하며 기록마다 최대 5개까지 사용합니다.
- 할 일의 마감일은 선택 사항이며 새 할 일은 미완료로 시작합니다.
- 오류를 해결됨으로 바꿀 때는 해결 방법을 반드시 입력합니다.
- 목록은 한 번에 20개, 대시보드는 종류별 5개 항목을 보여줍니다.
- 검색어와 여러 필터를 동시에 사용할 수 있고 영문 대소문자를 구분하지 않습니다.
- 신고 기능은 첫 번째 버전에서 만들지 않고, 공개 기능을 검토할 때 함께 다시 검토합니다.
- 실제 배포 서비스는 개발 완료 시점의 무료 요금과 제한을 비교한 뒤 선택합니다.

## 13. 기술 구성

`mvp.md`에서 권장한 기본 구성은 다음과 같습니다.

- 프론트엔드: React
- 백엔드: Python과 FastAPI
- 현재 데이터베이스: SQLite3
- 자동 테스트 데이터베이스: 메모리 SQLite3
- 화면 스타일: 단순한 CSS부터 시작
- 배포: 무료 요금제를 제공하는 서비스를 우선 검토

프론트엔드와 백엔드는 분리합니다. React는 FastAPI를 통해 기능을 사용하고, FastAPI가 권한 확인과 데이터 저장을 처리합니다. 현재 데이터는 프로젝트 내부 SQLite3에 저장하며 자동 테스트는 별도의 메모리 SQLite3에서 실행합니다. 회원 가입과 로그인은 FastAPI에서 처리합니다.

각 폴더의 역할은 다음과 같습니다.

```text
buildlog/
├── frontend/   # 사용자가 보는 웹 화면
├── backend/    # 로그인, 권한 확인, 저장과 검색 처리
├── database/   # 데이터베이스 설계와 변경 기록
└── docs/       # 기획과 사용 방법 문서
```

현재 데이터베이스는 SQLite3로 확정했습니다. Supabase 연동은 관련 수업 이후 별도 단계에서 검토합니다. 프론트엔드와 백엔드의 구체적인 배포 서비스는 개발 완료 시점의 무료 요금과 제한을 확인한 뒤 선택합니다.
