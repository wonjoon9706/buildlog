# BuildLog 기능 동작 설명서

## 1. 문서 목적

이 문서는 `PRD.md`에 정해진 BuildLog 첫 번째 버전의 기능이 실제로 어떻게 동작해야 하는지 설명합니다. 개발자뿐 아니라 비전공자도 기능의 입력, 결과, 실패 상황, 권한과 확인 방법을 이해할 수 있도록 작성했습니다.

이 문서는 `PRD.md`와 이후 사용자 답변으로 확정한 조건만 사용합니다.

### 구현 구성

- 사용자가 보는 화면은 React로 만듭니다.
- 회원 가입, 로그인, 권한 확인과 기록 처리는 FastAPI가 담당합니다.
- React는 FastAPI를 통해서만 개인 기록을 읽고 저장합니다.
- 실제 서비스 데이터는 Supabase 데이터베이스에 저장합니다.
- 자동 테스트에서는 실제 서비스 데이터와 분리된 SQLite3 데이터베이스를 사용합니다.
- 회원 가입과 로그인은 FastAPI에서 처리하며 Supabase Auth는 첫 번째 버전에서 사용하지 않습니다.

## 2. 공통 동작 원칙

- BuildLog는 여러 사람이 각자 가입해서 사용하는 웹사이트입니다.
- 개인 기록은 모두 비공개이며 작성자 본인만 볼 수 있습니다.
- 로그인하지 않은 사용자는 대시보드와 개인 기록 화면을 이용할 수 없습니다.
- 로그인한 사용자도 다른 사용자의 기록을 보거나 수정하거나 삭제할 수 없습니다.
- 저장에 성공하거나 입력 또는 처리에 문제가 생기면 사용자가 이해할 수 있는 안내 문구를 보여줍니다.
- 삭제 버튼을 누르면 바로 지우지 않고 정말 삭제할 것인지 한 번 더 확인합니다.
- 컴퓨터와 휴대폰에서 같은 주요 기능을 사용할 수 있어야 합니다.
- 새로고침하거나 다시 로그인해도 정상적으로 저장한 기록은 유지되어야 합니다.

## 3. 회원 가입

### 3.1 사용자의 행동과 입력

1. 사용자가 회원 가입 화면으로 이동합니다.
2. 이메일과 비밀번호를 입력합니다.
3. 가입 버튼을 누릅니다.

입력 조건은 다음과 같습니다.

- 이메일은 일반적인 이메일 형식이어야 합니다.
- 비밀번호는 8자 이상이어야 합니다.

### 3.2 정상 처리 결과

- 새로운 사용자 번호, 이메일, 안전하게 변환된 비밀번호와 가입일이 저장됩니다.
- 입력한 비밀번호 원문은 저장하지 않습니다.
- 화면에는 가입 성공 안내가 나타납니다.
- 가입에 성공하면 바로 로그인된 상태가 되고 대시보드로 이동합니다.

### 3.3 잘못 입력하거나 실패한 경우

- 이미 가입된 이메일이면 새 계정을 만들지 않고 실패 안내를 보여줍니다.
- 입력값이 정해진 조건에 맞지 않으면 계정을 만들지 않고 어떤 입력을 확인해야 하는지 안내합니다.
- 저장 처리에 실패하면 계정이 만들어졌다고 표시하지 않고 실패 안내를 보여줍니다.

### 3.4 보기·수정·삭제 권한

- 가입 전에는 누구나 회원 가입 화면을 사용할 수 있습니다.
- 다른 사용자의 계정 정보나 비밀번호는 볼 수 없습니다.
- 계정 정보 수정과 회원 탈퇴 기능은 PRD에 없으므로 첫 번째 버전에서 제공하지 않습니다.

### 3.5 완성 확인 방법

- 처음 사용하는 이메일과 비밀번호로 가입했을 때 계정이 만들어지고 성공 안내가 나오는지 확인합니다.
- 가입 직후 별도의 로그인 없이 대시보드로 이동하는지 확인합니다.
- 같은 이메일로 다시 가입했을 때 두 번째 계정이 만들어지지 않는지 확인합니다.
- 잘못된 입력을 보냈을 때 계정이 저장되지 않고 안내가 나오는지 확인합니다.
- 저장된 비밀번호가 사용자가 입력한 원문 그대로가 아닌지 확인합니다.

## 4. 로그인과 로그아웃

### 4.1 사용자의 행동과 입력

1. 사용자가 로그인 화면으로 이동합니다.
2. 가입한 이메일과 비밀번호를 입력합니다.
3. 로그인 버튼을 누릅니다.
4. 사용을 마치면 로그아웃 버튼을 누릅니다.

### 4.2 정상 처리 결과

- 이메일과 비밀번호가 맞으면 로그인 상태가 됩니다.
- 로그인한 뒤에는 대시보드와 자신의 기록 화면을 사용할 수 있습니다.
- 로그아웃하면 로그인 상태가 끝나고 개인 기록 화면을 더 이상 이용할 수 없습니다.
- 로그인 상태는 로그인한 기기에서 7일 동안 유지됩니다.

### 4.3 잘못 입력하거나 실패한 경우

- 이메일 또는 비밀번호가 맞지 않으면 로그인되지 않습니다.
- 화면에는 로그인 정보를 다시 확인할 수 있는 쉬운 안내를 보여줍니다.
- 로그인 처리에 실패하면 개인 기록 화면으로 이동시키지 않습니다.

### 4.4 보기·수정·삭제 권한

- 로그인한 사용자는 자신의 대시보드와 기록만 이용할 수 있습니다.
- 로그인하지 않은 사용자는 개인 기록을 볼 수 없습니다.
- 다른 사용자의 기록 주소로 접근하더라도 내용을 보여주거나 고치거나 삭제하게 해서는 안 됩니다.

### 4.5 완성 확인 방법

- 올바른 정보로 로그인했을 때 대시보드를 이용할 수 있는지 확인합니다.
- 잘못된 비밀번호로 로그인했을 때 로그인되지 않고 안내가 나오는지 확인합니다.
- 로그아웃한 뒤 개인 기록 화면에 다시 접근할 수 없는지 확인합니다.
- 두 계정을 만들어 서로의 기록을 볼 수 없는지 확인합니다.

## 5. 대시보드

### 5.1 사용자의 행동

1. 사용자가 로그인합니다.
2. 로그인 후 홈 화면인 대시보드로 이동합니다.
3. 원하는 항목을 누르거나 전체 목록으로 이동하는 버튼을 누릅니다.

### 5.2 정상 처리 결과

대시보드에는 로그인한 사용자의 다음 정보만 보입니다.

- 최근 학습 기록
- 완료하지 않은 할 일
- 아직 해결하지 못한 오류
- 학습 기록, 할 일, 오류 기록의 전체 목록으로 이동하는 버튼

각 영역에는 5개 항목을 보여줍니다. 학습 기록은 공부한 날짜가 최신인 순서, 할 일은 미완료이면서 마감일이 가까운 순서, 오류 기록은 최근 수정한 순서로 보여줍니다. 마감일이 없는 할 일은 마감일이 있는 할 일 다음에 보여줍니다.

### 5.3 처리에 실패한 경우

- 정보를 불러오지 못하면 성공한 것처럼 빈 목록만 보여주지 않고 불러오지 못했다는 안내를 보여줍니다.
- 로그인 상태가 아니라면 개인 정보를 보여주지 않습니다.

### 5.4 보기·수정·삭제 권한

- 로그인한 본인만 자신의 대시보드를 볼 수 있습니다.
- 대시보드에는 다른 사용자의 기록이 나타나면 안 됩니다.
- 대시보드는 내용을 요약해서 보여주는 화면이며, 실제 수정과 삭제는 각 기능의 화면에서 처리합니다.

### 5.5 완성 확인 방법

- 학습 기록, 미완료 할 일, 미해결 오류를 각각 만든 뒤 대시보드에 나타나는지 확인합니다.
- 할 일을 완료하거나 오류를 해결됨으로 바꾸면 해당 미완료·미해결 영역에서 상태가 올바르게 반영되는지 확인합니다.
- 각 전체 목록 버튼이 올바른 화면으로 이동하는지 확인합니다.
- 다른 사용자의 항목이 섞이지 않는지 확인합니다.

## 6. 학습 기록

### 6.1 학습 기록 작성

#### 사용자의 행동과 입력

1. 사용자가 학습 기록 목록에서 새 기록 작성 버튼을 누릅니다.
2. 제목, 내용, 공부한 날짜와 태그를 입력합니다.
3. 저장 버튼을 누릅니다.

입력 조건은 다음과 같습니다.

- 제목, 내용과 공부한 날짜는 필수입니다.
- 태그는 선택 사항입니다.
- 제목은 최대 100자, 내용은 최대 20,000자입니다.
- 태그는 최대 5개까지 추가할 수 있고, 태그 하나는 최대 20자입니다.
- 태그 내용을 입력하고 `Enter`를 누르면 태그가 추가됩니다.

#### 정상 처리 결과

- 제목, 내용, 공부한 날짜, 태그, 작성일, 수정일과 작성한 사용자가 저장됩니다.
- 저장 성공 안내가 나타납니다.
- 저장한 기록을 목록과 상세 화면에서 확인할 수 있습니다.
- 작성한 마크다운은 상세 화면에서 제목, 목록, 링크와 코드 블록이 읽기 좋은 모습으로 표시됩니다.

#### 잘못 입력하거나 실패한 경우

- 제목, 내용 또는 공부한 날짜가 빠져 있으면 저장하지 않고 확인할 항목을 안내합니다.
- 제목 100자, 내용 20,000자, 태그 5개 또는 태그 하나당 20자를 넘으면 저장하지 않고 입력 조건을 안내합니다.
- 저장 처리에 실패하면 성공했다고 표시하지 않고 실패 안내를 보여줍니다.

#### 보기·수정·삭제 권한

- 로그인한 사용자만 기록을 작성할 수 있습니다.
- 작성한 본인만 해당 기록을 볼 수 있습니다.

#### 완성 확인 방법

- 네 가지 입력 항목을 작성하고 저장했을 때 목록과 상세 화면에 같은 내용이 나타나는지 확인합니다.
- 마크다운 제목, 목록, 링크와 코드 블록이 상세 화면에서 읽기 좋게 표시되는지 확인합니다.
- 새로고침하고 다시 로그인해도 기록이 남아 있는지 확인합니다.
- 다른 계정에서는 해당 기록이 보이지 않는지 확인합니다.

### 6.2 학습 기록 목록과 상세 보기

#### 사용자의 행동

1. 사용자가 `학습 기록` 메뉴를 누릅니다.
2. 목록에서 원하는 기록을 누릅니다.

#### 정상 처리 결과

- 목록에는 로그인한 사용자의 학습 기록만 나타납니다.
- 상세 화면에는 선택한 기록의 제목, 내용, 공부한 날짜, 태그와 작성·수정 정보가 나타납니다.
- 내용은 마크다운이 적용된 읽기 좋은 모습으로 보입니다.
- 목록은 공부한 날짜가 최신인 순서로 한 번에 20개씩 보여줍니다.

#### 처리에 실패한 경우

- 목록이나 상세 내용을 불러오지 못하면 실패 안내를 보여줍니다.
- 존재하지 않거나 본인의 것이 아닌 기록은 내용을 보여주지 않습니다.

#### 보기·수정·삭제 권한

- 작성한 본인만 목록과 상세 내용을 볼 수 있습니다.
- 다른 사용자와 로그인하지 않은 사용자는 볼 수 없습니다.

#### 완성 확인 방법

- 여러 기록을 만든 뒤 목록과 상세 화면에 올바른 내용이 나타나는지 확인합니다.
- 다른 계정이나 로그아웃 상태에서 기록이 보이지 않는지 확인합니다.

### 6.3 학습 기록 수정

#### 사용자의 행동과 입력

1. 상세 화면에서 수정 버튼을 누릅니다.
2. 제목, 내용, 공부한 날짜 또는 태그를 고칩니다.
3. 저장 버튼을 누릅니다.

#### 정상 처리 결과

- 변경한 내용과 수정일이 저장됩니다.
- 저장 성공 안내가 나타납니다.
- 목록과 상세 화면에 수정한 내용이 보입니다.

#### 잘못 입력하거나 실패한 경우

- 입력 조건에 맞지 않으면 변경 내용을 저장하지 않고 안내합니다.
- 처리에 실패하면 수정에 성공했다고 표시하지 않습니다.

#### 보기·수정·삭제 권한

- 작성한 본인만 수정할 수 있습니다.
- 다른 사용자는 수정할 수 없습니다.

#### 완성 확인 방법

- 각 입력 항목을 바꿔 저장한 뒤 변경 내용과 수정일이 반영되는지 확인합니다.
- 다른 계정에서 수정할 수 없는지 확인합니다.

### 6.4 학습 기록 삭제

#### 사용자의 행동

1. 상세 화면에서 삭제 버튼을 누릅니다.
2. 삭제 확인 안내에서 삭제를 선택합니다.

#### 정상 처리 결과

- 선택한 기록이 삭제됩니다.
- 삭제한 기록은 목록과 상세 화면에서 더 이상 보이지 않습니다.

#### 취소하거나 실패한 경우

- 확인 안내에서 취소하면 기록은 삭제되지 않습니다.
- 삭제 처리에 실패하면 기록을 유지하고 실패 안내를 보여줍니다.

#### 보기·수정·삭제 권한

- 작성한 본인만 삭제할 수 있습니다.

#### 완성 확인 방법

- 삭제를 취소했을 때 기록이 남는지 확인합니다.
- 삭제를 확인했을 때 목록과 상세 화면에서 사라지는지 확인합니다.
- 다른 계정에서 삭제할 수 없는지 확인합니다.

## 7. 할 일

### 7.1 할 일 작성과 보기

#### 사용자의 행동과 입력

1. 사용자가 `할 일` 메뉴로 이동합니다.
2. 할 일 내용과 마감일을 입력합니다.
3. 추가 또는 저장 버튼을 누릅니다.

할 일 내용은 필수이고 마감일은 선택 사항입니다.

#### 정상 처리 결과

- 할 일 내용, 마감일, 완료 여부, 작성일, 수정일과 작성한 사용자가 저장됩니다.
- 새 할 일은 `미완료` 상태로 저장됩니다.
- 저장 성공 안내가 나타나고 자신의 할 일 목록에서 확인할 수 있습니다.
- 남은 할 일과 끝난 할 일을 구분해서 볼 수 있습니다.
- 미완료와 완료한 할 일을 나누어 모두 보여줍니다.
- 미완료 할 일은 가까운 마감일 순서로 보여주며 마감일이 없는 항목은 그다음에 보여줍니다.
- 완료한 할 일은 최근 수정한 순서로 보여줍니다.
- 목록은 한 번에 20개씩 보여줍니다.

#### 잘못 입력하거나 실패한 경우

- 필수 입력값이 빠졌거나 입력 조건에 맞지 않으면 저장하지 않고 안내합니다.
- 저장 또는 목록 불러오기에 실패하면 실패 안내를 보여줍니다.

#### 보기·수정·삭제 권한

- 로그인한 본인만 자신의 할 일을 작성하고 볼 수 있습니다.
- 다른 사용자와 로그인하지 않은 사용자는 볼 수 없습니다.

#### 완성 확인 방법

- 할 일을 추가한 뒤 목록에 같은 내용과 마감일이 나타나는지 확인합니다.
- 새로고침하고 다시 로그인해도 저장된 할 일이 남아 있는지 확인합니다.
- 다른 계정에 해당 할 일이 나타나지 않는지 확인합니다.

### 7.2 완료 여부 변경

#### 사용자의 행동

- 사용자가 할 일 옆의 체크 상자를 누릅니다.

#### 정상 처리 결과

- 미완료 상태는 완료 상태로, 완료 상태는 미완료 상태로 바뀝니다.
- 변경된 완료 여부와 수정일이 저장됩니다.
- 남은 할 일과 끝난 할 일 구분에 변경 결과가 반영됩니다.

#### 처리에 실패한 경우

- 변경에 실패하면 실제 저장 상태와 다르게 완료되었다고 표시하지 않고 실패 안내를 보여줍니다.

#### 보기·수정·삭제 권한

- 작성한 본인만 완료 여부를 바꿀 수 있습니다.

#### 완성 확인 방법

- 체크 상자를 누른 뒤 완료 상태가 바뀌고 새로고침 후에도 유지되는지 확인합니다.
- 다시 눌러 미완료로 되돌릴 수 있는지 확인합니다.
- 다른 계정에서 상태를 바꿀 수 없는지 확인합니다.

### 7.3 할 일 수정과 삭제

#### 정상 처리 결과

- 삭제하면 해당 할 일이 목록에서 사라집니다.

#### 잘못 입력하거나 실패한 경우

- 삭제 확인에서 취소하면 삭제하지 않습니다.
- 수정 또는 삭제 처리에 실패하면 성공했다고 표시하지 않고 기존 저장 상태를 유지합니다.

#### 보기·수정·삭제 권한

#### 완성 확인 방법

- 내용과 마감일을 수정한 뒤 변경 결과가 유지되는지 확인합니다.
- 삭제를 취소하면 남아 있고, 확인하면 사라지는지 확인합니다.
- 다른 계정에서 수정하거나 삭제할 수 없는지 확인합니다.

### 7.4 미완료 할 일만 보기

## 8. 오류 기록

### 8.1 오류 기록 작성

#### 사용자의 행동과 입력

1. 사용자가 오류 기록 목록에서 새 오류 작성 버튼을 누릅니다.
2. 오류 제목, 실제 오류 메시지, 발생 상황, 해결 여부, 해결 방법과 태그를 입력합니다.
3. 저장 버튼을 누릅니다.

해결하지 못한 오류는 해결 방법 없이 먼저 저장할 수 있습니다.

입력 조건은 다음과 같습니다.

- 오류 제목, 오류 메시지와 발생 상황은 필수입니다.
- 해결 방법과 태그는 선택 사항입니다.
- 오류 제목은 최대 100자입니다.
- 오류 메시지, 발생 상황과 해결 방법은 각각 최대 20,000자입니다.
- 태그는 최대 5개까지 추가할 수 있고, 태그 하나는 최대 20자입니다.
- 태그 내용을 입력하고 `Enter`를 누르면 태그가 추가됩니다.
- 상태를 `해결됨`으로 저장하려면 해결 방법을 반드시 입력해야 합니다.

#### 정상 처리 결과

- 입력한 정보, 작성일, 수정일과 작성한 사용자가 저장됩니다.
- 저장 성공 안내가 나타납니다.
- 목록과 상세 화면에서 기록을 확인할 수 있습니다.

#### 잘못 입력하거나 실패한 경우

- 오류 제목, 오류 메시지 또는 발생 상황이 빠져 있으면 저장하지 않고 안내합니다.
- 정해진 글자 수나 태그 수를 넘으면 저장하지 않고 안내합니다.
- 해결 방법 없이 상태를 `해결됨`으로 선택하면 저장하지 않고 해결 방법 입력을 안내합니다.
- 저장 처리에 실패하면 성공했다고 표시하지 않고 실패 안내를 보여줍니다.

#### 보기·수정·삭제 권한

- 로그인한 사용자만 오류 기록을 작성할 수 있습니다.
- 작성한 본인만 기록을 볼 수 있습니다.

#### 완성 확인 방법

- 미해결 오류를 해결 방법 없이 저장할 수 있는지 확인합니다.
- 입력한 오류 정보가 목록과 상세 화면에 올바르게 나타나는지 확인합니다.
- 새로고침하고 다시 로그인해도 기록이 유지되는지 확인합니다.
- 다른 계정에 해당 기록이 보이지 않는지 확인합니다.

### 8.2 오류 기록 목록과 상세 보기

#### 사용자의 행동

1. 사용자가 `오류 기록` 메뉴를 누릅니다.
2. 목록에서 원하는 오류를 누릅니다.

#### 정상 처리 결과

- 목록에는 로그인한 사용자의 오류 기록만 나타납니다.
- 상세 화면에는 오류 제목, 오류 메시지, 발생 상황, 해결 여부, 해결 방법, 태그와 작성·수정 정보가 나타납니다.
- 목록은 최근 수정한 순서로 한 번에 20개씩 보여줍니다.

#### 처리에 실패한 경우

- 목록이나 상세 내용을 불러오지 못하면 실패 안내를 보여줍니다.
- 존재하지 않거나 본인의 것이 아닌 기록은 내용을 보여주지 않습니다.

#### 보기·수정·삭제 권한

- 작성한 본인만 목록과 상세 내용을 볼 수 있습니다.

#### 완성 확인 방법

- 여러 오류 기록을 만든 뒤 목록과 상세 정보가 맞는지 확인합니다.
- 다른 계정과 로그아웃 상태에서 기록이 보이지 않는지 확인합니다.

### 8.3 오류 기록 수정과 해결 처리

#### 사용자의 행동과 입력

1. 사용자가 오류 상세 화면에서 수정 버튼을 누릅니다.
2. 필요한 내용을 고칩니다.
3. 오류를 해결했다면 해결 방법을 입력하고 상태를 `해결됨`으로 바꿉니다.
4. 저장 버튼을 누릅니다.

#### 정상 처리 결과

- 변경한 내용, 해결 여부와 수정일이 저장됩니다.
- 저장 성공 안내가 나타납니다.
- 목록과 상세 화면에 변경 결과가 반영됩니다.

#### 잘못 입력하거나 실패한 경우

- 입력 조건에 맞지 않으면 변경 내용을 저장하지 않고 안내합니다.
- 해결 방법 없이 `해결됨` 상태로 저장하려 하면 저장하지 않고 해결 방법 입력을 안내합니다.
- 처리에 실패하면 해결되었다고 표시하지 않고 실패 안내를 보여줍니다.

#### 보기·수정·삭제 권한

- 작성한 본인만 수정하거나 해결 상태를 바꿀 수 있습니다.

#### 완성 확인 방법

- 미해결 기록에 해결 방법을 추가하고 `해결됨`으로 바꿀 수 있는지 확인합니다.
- 새로고침 후에도 해결 상태와 해결 방법이 유지되는지 확인합니다.
- 다른 계정에서 수정할 수 없는지 확인합니다.

### 8.4 오류 기록 삭제

#### 사용자의 행동

1. 상세 화면에서 삭제 버튼을 누릅니다.

#### 정상 처리 결과

#### 취소하거나 실패한 경우

- 확인 안내에서 취소하면 기록은 삭제되지 않습니다.
- 삭제 처리에 실패하면 기록을 유지하고 실패 안내를 보여줍니다.

#### 보기·수정·삭제 권한

- 작성한 본인만 삭제할 수 있습니다.

#### 완성 확인 방법

- 삭제 취소와 삭제 확인을 각각 실행해 올바르게 처리되는지 확인합니다.
- 다른 계정에서 삭제할 수 없는지 확인합니다.

### 8.5 미해결 오류만 보기

#### 사용자의 행동

#### 완성 확인 방법

- 로그인한 본인의 기록만 결과에 포함됩니다.

#### 완성 확인 방법

- 서로 다른 날짜의 기록을 만든 뒤 선택한 날짜에 맞는 기록만 나타나는지 확인합니다.

### 9.5 검색과 여러 필터 함께 사용

- 검색어, 태그, 날짜와 상태 조건을 동시에 사용할 수 있습니다.
- 여러 조건을 사용하면 모든 조건에 맞는 기록만 나타납니다.
- 영문 대문자와 소문자를 구분하지 않고 검색합니다.
- 학습 기록과 오류 기록은 각각의 목록에서 검색합니다.
- 학습 기록, 할 일, 오류 기록을 한꺼번에 찾는 통합 검색은 첫 번째 버전에서 만들지 않습니다.

확인할 때에는 결정된 조건을 함께 선택하고, 모든 조건에 맞는 본인의 기록만 나타나는지 검사합니다.

## 10. 공개와 비공개

### 10.1 사용자의 행동

- 사용자가 공개 범위를 선택하거나 바꾸는 동작은 없습니다.
- 첫 번째 버전의 모든 학습 기록, 할 일과 오류 기록은 자동으로 비공개입니다.

### 10.2 정상 처리 결과

- 저장한 기록은 작성한 사용자의 계정에서만 보입니다.
- 다른 사람에게 공개하는 페이지나 공유 링크는 만들어지지 않습니다.

### 10.3 처리에 실패한 경우

- 로그인하지 않았거나 작성자가 아닌 사용자가 접근하면 기록 내용을 보여주지 않습니다.

### 10.4 보기·수정·삭제 권한

- 작성한 본인만 보고, 수정하고, 삭제할 수 있습니다.
- 다른 사용자는 어떤 개인 기록에도 접근할 수 없습니다.

### 10.5 완성 확인 방법

- 두 개의 계정으로 각각 기록을 만든 뒤 서로의 기록이 목록, 검색 결과, 대시보드와 직접 접근에서 모두 보이지 않는지 확인합니다.
- 로그아웃한 상태에서 개인 기록이 보이지 않는지 확인합니다.

## 11. 화면과 공통 사용 경험

### 11.1 사용자의 행동

- 사용자는 `홈`, `학습 기록`, `할 일`, `오류 기록` 메뉴로 이동합니다.
- 작성 버튼과 저장 버튼을 눌러 주요 작업을 실행합니다.

### 11.2 정상 처리 결과

- 기본 화면은 밝은 색으로 보입니다.
- 메뉴와 안내 문구는 쉬운 한국어로 표시됩니다.
- 작성 버튼과 저장 버튼을 쉽게 찾을 수 있습니다.
- 컴퓨터에서는 넓은 화면을 활용하고, 휴대폰에서는 내용이 화면 밖으로 벗어나지 않으며 세로로 자연스럽게 배치됩니다.

대표 색상은 파란색 계열을 사용하고 글꼴은 사용 중인 기기의 기본 글꼴을 사용합니다. 로고는 별도 그림 없이 `BuildLog` 글자로 표시합니다. 컴퓨터에서는 메뉴를 화면 위쪽에 배치하고, 휴대폰에서는 메뉴 버튼을 눌러 메뉴를 엽니다.

### 11.3 처리에 실패한 경우

- 저장, 로그인 또는 목록 불러오기 등에 실패하면 사용자가 실패 사실을 알 수 있는 안내를 보여줍니다.
- 화면이 좁아도 주요 내용과 버튼을 사용할 수 없어서는 안 됩니다.

### 11.4 보기·수정·삭제 권한

- 공용 화면인 회원 가입과 로그인 화면 외의 개인 화면은 로그인한 사용자만 이용할 수 있습니다.

### 11.5 완성 확인 방법

- 컴퓨터와 휴대폰 크기의 화면에서 메뉴, 입력칸, 버튼과 내용이 잘 보이고 사용할 수 있는지 확인합니다.
- 저장 성공, 입력 오류, 로그인 실패와 불러오기 실패 안내가 나타나는지 확인합니다.
- 모든 삭제 동작에서 확인 안내가 먼저 나타나는지 확인합니다.

## 12. 첫 번째 버전에서 지원하지 않는 기능

이 절의 기능은 PRD에 따라 이번에 개발하지 않습니다. 따라서 입력 화면, 저장 동작, 보기·수정·삭제 권한과 기능 확인 절차를 만들지 않습니다.

## 13. 추가로 확정한 내용

- 회원 가입에 성공하면 자동으로 로그인하고 대시보드로 이동합니다.
- 이메일은 일반적인 이메일 형식을 사용하고 비밀번호는 8자 이상 입력합니다.
- 로그인 상태는 7일 동안 유지합니다.
- 학습 기록과 오류 기록의 필수 항목, 글자 수와 태그 수를 제한합니다.
- 태그는 내용을 입력하고 `Enter`를 눌러 추가합니다.
- 할 일 마감일은 선택 사항이며 새 할 일은 미완료로 시작합니다.
- 오류를 해결됨으로 바꾸려면 해결 방법을 반드시 입력합니다.
- 목록은 한 번에 20개, 대시보드는 종류별 5개 항목을 보여줍니다.
- 미완료와 완료한 할 일을 나누어 모두 보여줍니다.
- 오류 검색은 제목, 메시지, 발생 상황과 해결 방법을 대상으로 합니다.
- 날짜는 시작일과 종료일을 고르며 학습 기록은 공부한 날짜, 오류 기록은 작성일을 기준으로 합니다.
- 검색어와 여러 필터를 동시에 사용할 수 있고 영문 대소문자를 구분하지 않습니다.
- 파란색 계열, 기기 기본 글꼴과 글자 로고를 사용합니다.
- 컴퓨터에는 위쪽 메뉴, 휴대폰에는 메뉴 버튼을 사용합니다.
- 신고 기능은 공개 기능을 검토할 때 다시 검토합니다.
- 실제 배포 서비스는 개발 완료 시점의 무료 요금과 제한을 확인한 뒤 선택합니다.

- [ ] 다른 사용자와 로그인하지 않은 사용자는 개인 기록을 볼 수 없다.
- [ ] 학습 기록을 작성, 조회, 수정, 삭제할 수 있다.
- [ ] 학습 기록의 마크다운과 코드 블록을 읽기 좋게 볼 수 있다.
- [ ] 할 일을 작성, 조회, 수정, 삭제할 수 있다.
- [ ] 할 일의 완료 여부를 바꿀 수 있다.
- [ ] 미완료 할 일만 볼 수 있다.
- [ ] 오류 기록을 작성, 조회, 수정, 삭제할 수 있다.
- [ ] 미해결 오류에 해결 방법을 추가하고 해결됨으로 바꿀 수 있다.
- [ ] 미해결 오류만 볼 수 있다.
- [ ] 학습 기록과 오류 기록을 각각 제목과 내용으로 검색할 수 있다.
- [ ] 학습 기록과 오류 기록을 태그와 날짜로 골라 볼 수 있다.
- [ ] 대시보드에 최근 학습 기록, 미완료 할 일과 미해결 오류가 보인다.
- [ ] 저장한 내용이 새로고침과 재로그인 후에도 유지된다.
- [ ] 모든 개인 정보와 기록이 작성자에게만 보인다.
- [ ] 컴퓨터와 휴대폰에서 주요 기능을 사용할 수 있다.
- [ ] 성공과 실패 안내가 필요한 상황에서 올바르게 나타난다.
- [ ] 삭제 전에 확인 안내가 나타난다.
- [ ] 첫 번째 버전에서 제외한 기능이 임의로 추가되지 않았다.
