# BuildLog MVP 기획서

## 1. BuildLog란?

BuildLog는 공부하면서 생긴 기록을 한곳에 모아두는 웹사이트입니다.

사용자는 오늘 공부한 내용, 앞으로 할 일, 공부 중 만난 오류와 해결 방법을 기록할 수 있습니다. 인터넷에 연결된 컴퓨터나 휴대폰에서 로그인하면 자신의 기록을 다시 확인할 수 있습니다.

이 문서에서 말하는 **MVP**는 꼭 필요한 기능만 넣어 먼저 완성하는 첫 번째 버전을 뜻합니다.

## 2. 만들려는 이유

공부 기록이 메모장과 AI 대화 등 여러 곳에 흩어지면 나중에 다시 찾기 어렵습니다. BuildLog는 다음과 같은 문제를 해결하려고 합니다.

- 오늘 무엇을 공부했는지 쉽게 잊어버리는 문제
- 해야 할 공부와 프로젝트 작업을 놓치는 문제
- 예전에 해결한 오류를 다시 만났을 때 해결 방법을 찾기 어려운 문제

## 3. 첫 번째 버전의 목표

BuildLog의 첫 번째 버전은 다음 경험을 제공하는 것을 목표로 합니다.

1. 누구나 이메일과 비밀번호로 가입할 수 있습니다.
2. 로그인한 사용자는 자신의 학습 기록을 작성하고 다시 볼 수 있습니다.
3. 해야 할 일을 적고 완료 여부를 체크할 수 있습니다.
4. 오류와 해결 과정을 별도로 기록할 수 있습니다.
5. 저장한 기록을 검색하거나 날짜와 태그로 찾을 수 있습니다.
6. 컴퓨터와 휴대폰에서 모두 편하게 사용할 수 있습니다.

## 4. 기본 원칙

- 모든 기록은 작성한 사용자 본인만 볼 수 있습니다.
- 화면과 사용 방법은 단순하고 이해하기 쉽게 만듭니다.
- 자주 사용하는 기능이 첫 화면에서 바로 보이게 합니다.
- 기능을 지나치게 많이 넣기보다 기록하고 다시 찾는 핵심 경험에 집중합니다.
- 서비스 운영에 필요한 비밀값은 코드에 직접 적지 않습니다.

## 5. MVP에 포함할 기능

### 5.1 회원 가입과 로그인

- 이메일과 비밀번호로 회원 가입
- 가입한 계정으로 로그인과 로그아웃
- 로그인하지 않은 사람은 개인 기록을 볼 수 없음
- 사용자마다 자신의 기록만 조회하고 수정할 수 있음

비밀번호는 원래 글자 그대로 저장하지 않고 안전하게 변환하여 저장합니다.

### 5.2 학습 기록

사용자는 공부한 내용을 작성하고 관리할 수 있습니다.

- 제목
- 내용
- 공부한 날짜
- 태그
- 작성일과 수정일
- 기록 작성, 조회, 수정, 삭제

내용에는 마크다운을 사용할 수 있습니다. 마크다운은 간단한 기호로 제목, 목록, 링크, 코드 블록 등을 표현하는 작성 방식입니다.

예시:

````md
## 오늘 배운 내용

- FastAPI 라우터 만들기
- 요청 데이터 검사하기

```python
print("Hello, BuildLog!")
```
````

### 5.3 할 일

앞으로 공부할 내용이나 프로젝트에서 해야 할 작업을 관리합니다.

- 할 일 내용
- 마감일
- 완료 여부
- 작성일과 수정일
- 할 일 작성, 조회, 수정, 삭제
- 체크 상자를 눌러 완료 또는 미완료로 변경
- 남은 할 일과 끝난 할 일을 구분해서 보기

예시:

- 저장 버튼 만들기
- 파이썬 복습하기

### 5.4 오류 기록

공부나 개발 중 만난 오류와 해결 과정을 따로 저장합니다.

- 오류 제목
- 실제 오류 메시지
- 오류가 발생한 상황
- 해결 여부
- 해결 방법
- 태그
- 작성일과 수정일
- 오류 기록 작성, 조회, 수정, 삭제

아직 해결하지 못한 오류도 저장할 수 있습니다. 나중에 해결하면 상태를 `해결됨`으로 바꾸고 해결 방법을 추가합니다.

### 5.5 검색과 필터

저장한 기록을 쉽게 다시 찾을 수 있어야 합니다.

- 제목과 내용에 포함된 단어로 검색
- 태그별로 보기
- 날짜별로 보기
- 해결하지 못한 오류만 보기
- 완료하지 않은 할 일만 보기

MVP에서는 학습 기록과 오류 기록을 각각 검색합니다. 모든 종류의 기록을 한 번에 찾는 통합 검색은 이후에 추가할 수 있습니다.

### 5.6 대시보드

로그인 후 가장 먼저 보는 화면입니다. 현재 상황을 한눈에 확인할 수 있도록 다음 정보를 보여줍니다.

- 최근 학습 기록
- 완료하지 않은 할 일
- 아직 해결하지 못한 오류
- 각 항목의 전체 목록으로 이동하는 버튼

## 6. 필요한 화면

| 화면 | 사용자가 할 수 있는 일 |
| --- | --- |
| 회원 가입 | 이메일과 비밀번호로 계정 만들기 |
| 로그인 | 계정에 로그인하기 |
| 대시보드 | 최근 기록, 남은 할 일, 미해결 오류 확인하기 |
| 학습 기록 목록 | 기록 검색, 태그·날짜 필터, 상세 화면 이동 |
| 학습 기록 작성·수정 | 제목, 내용, 날짜, 태그 입력하기 |
| 학습 기록 상세 | 저장한 내용을 읽고 수정하거나 삭제하기 |
| 할 일 목록 | 할 일을 추가하고 완료 여부 체크하기 |
| 오류 기록 목록 | 해결 여부, 태그, 날짜로 기록 찾기 |
| 오류 기록 작성·수정 | 오류 내용과 해결 방법 입력하기 |
| 오류 기록 상세 | 오류와 해결 과정을 읽고 수정하거나 삭제하기 |

작성과 수정은 같은 화면을 재사용할 수 있습니다. 이렇게 하면 개발해야 할 화면 수를 줄이고 사용 방법도 일관되게 만들 수 있습니다.

## 7. 주요 사용 흐름

### 처음 사용하는 경우

1. 회원 가입 화면에서 이메일과 비밀번호를 입력합니다.
2. 가입에 성공하면 자동으로 로그인됩니다.
3. 자동으로 이동한 대시보드에서 현재 상황을 확인합니다.
4. 학습 기록, 할 일 또는 오류 기록을 작성합니다.

### 공부한 내용을 기록하는 경우

1. `학습 기록 추가` 버튼을 누릅니다.
2. 제목, 내용, 공부한 날짜와 태그를 입력합니다.
3. 저장 버튼을 누릅니다.
4. 저장된 기록을 상세 화면에서 확인합니다.

### 오류를 나중에 해결하는 경우

1. 오류가 발생했을 때 오류 메시지와 상황을 저장합니다.
2. 상태를 `미해결`로 둡니다.
3. 문제를 해결한 뒤 해당 기록을 다시 엽니다.
4. 해결 방법을 작성하고 상태를 `해결됨`으로 바꿉니다.

### 예전 기록을 찾는 경우

1. 학습 기록 또는 오류 기록 목록으로 이동합니다.
2. 기억나는 단어를 검색창에 입력합니다.
3. 필요하면 태그나 날짜 조건을 추가합니다.
4. 검색 결과에서 원하는 기록을 선택합니다.

## 8. 저장할 데이터

데이터베이스는 서비스의 정보를 정리해서 보관하는 공간입니다. MVP에서는 다음 정보를 저장합니다.

### 사용자

- 사용자 번호
- 이메일
- 안전하게 변환된 비밀번호
- 가입일

### 학습 기록

- 기록 번호
- 작성한 사용자 번호
- 제목
- 내용
- 공부한 날짜
- 태그
- 작성일과 수정일

### 할 일

- 할 일 번호
- 작성한 사용자 번호
- 내용
- 마감일
- 완료 여부
- 작성일과 수정일

### 오류 기록

- 오류 기록 번호
- 작성한 사용자 번호
- 제목
- 오류 메시지
- 발생 상황
- 해결 여부
- 해결 방법
- 태그
- 작성일과 수정일

모든 학습 기록, 할 일, 오류 기록에는 작성자의 사용자 번호가 연결됩니다. 이를 이용해 다른 사용자의 기록이 섞이거나 노출되지 않도록 합니다.

## 9. 추천 개발 구성

처음 배우면서 만들기 쉽고 각 부분의 역할을 이해할 수 있도록 다음과 같이 나눕니다.

- **프론트엔드:** 사용자가 보는 화면과 버튼을 담당합니다.
- **백엔드:** 로그인, 권한 확인, 저장과 검색 같은 규칙을 처리합니다.
- **데이터베이스:** 사용자와 기록을 보관합니다.

기술은 다음 구성으로 확정합니다.

- 프론트엔드: React
- 백엔드: Python과 FastAPI
- 현재 데이터베이스: SQLite3
- 자동 테스트 데이터베이스: 메모리 SQLite3
- 화면 스타일: 단순한 CSS부터 시작
- 배포: 무료 요금제를 제공하는 서비스를 우선 검토

프론트엔드와 백엔드는 분리해서 개발합니다. React 화면은 FastAPI에 요청하고, FastAPI가 데이터 저장과 권한 확인을 담당합니다. 현재 데이터는 프로젝트 내부 SQLite3에 저장하고 자동 테스트에서는 별도의 메모리 SQLite3를 사용합니다. 회원 가입과 로그인도 FastAPI 백엔드에서 처리합니다.

프론트엔드와 백엔드의 특정 배포 서비스는 개발이 끝날 무렵 무료 요금과 제한을 다시 확인한 뒤 결정합니다. Supabase 연동은 관련 수업을 진행한 뒤 별도 단계에서 검토합니다.

현재 프로젝트 폴더는 다음 역할로 사용합니다.

```text
buildlog/
├── frontend/   # 사용자가 보는 웹 화면
├── backend/    # 로그인과 기록 처리 기능
├── database/   # 데이터베이스 설계와 변경 기록
└── docs/       # 기획과 사용 방법 문서
```

## 10. 디자인 방향

- 밝은 화면을 기본으로 사용합니다.
- 메뉴 이름은 쉬운 한국어로 표시합니다.
- 주요 메뉴는 `홈`, `학습 기록`, `할 일`, `오류 기록`으로 구성합니다.
- 작성 버튼과 저장 버튼은 눈에 잘 띄게 만듭니다.
- 컴퓨터에서는 넓은 화면을 활용하고, 휴대폰에서는 항목이 세로로 자연스럽게 배치되도록 합니다.
- 삭제처럼 되돌리기 어려운 동작은 한 번 더 확인합니다.
- 저장 성공과 입력 오류를 사용자가 알 수 있도록 안내 문구를 보여줍니다.

## 11. MVP에서 제외할 기능

다음 기능은 유용하지만 첫 번째 버전을 빠르게 완성하기 위해 제외합니다.

- 다른 사용자에게 기록 공개 또는 공유
- 이미지와 파일 첨부
- 할 일 중요도
- 다크 모드
- 댓글과 좋아요
- 신고
- 소셜 로그인
- 이메일 인증과 비밀번호 찾기
- 공부 시간 통계와 차트
- 실시간 알림
- 모바일 앱

필요해지면 웹사이트 MVP를 완성한 뒤 우선순위를 정해 추가합니다.

## 12. 개발 순서

1. 화면 구조와 데이터베이스 구조 정하기
2. 백엔드와 데이터베이스 연결하기
3. 회원 가입, 로그인, 로그아웃 만들기
4. 학습 기록 작성·조회·수정·삭제 만들기
5. 할 일 작성과 완료 체크 만들기
6. 오류 기록 작성과 해결 상태 변경 만들기
7. 검색, 태그, 날짜 필터 만들기
8. 대시보드 만들기
9. 휴대폰 화면에 맞게 다듬기
10. 사용 흐름과 보안을 점검한 뒤 배포하기

각 단계가 끝날 때마다 직접 사용해 보고 다음 단계로 넘어갑니다.

## 13. MVP 완료 기준

아래 항목을 모두 만족하면 첫 번째 버전이 완성된 것으로 봅니다.

- 새로운 사용자가 가입하고 로그인할 수 있음
- 로그인한 사용자가 자신의 기록만 볼 수 있음
- 학습 기록을 작성, 조회, 수정, 삭제할 수 있음
- 할 일을 추가하고 완료 여부를 바꿀 수 있음
- 미해결 오류를 저장하고 나중에 해결 방법을 추가할 수 있음
- 제목과 내용으로 기록을 검색할 수 있음
- 태그와 날짜로 기록을 골라 볼 수 있음
- 대시보드에서 최근 기록, 남은 할 일, 미해결 오류를 확인할 수 있음
- 컴퓨터와 휴대폰에서 주요 기능을 사용할 수 있음
- 새로고침하거나 다시 로그인해도 저장한 내용이 유지됨
- 비밀 설정 파일과 비밀번호가 공개되지 않음
